# 药苑之声异步选曲建议

主站「AI 配置」新增独立的歌曲审核场景，可分别设置开关、服务、模型、回退服务/模型及选曲规则。默认关闭，部署代码不会自动启用或开始清理存量投稿。

## 投稿流程

1. 投稿按原有流程立即保存，不同步等待 AI，不因 AI 建议拒绝或删除投稿。
2. VoiceHub 后台任务每 30 秒处理一首待审歌曲，优先新投稿。待审状态持久化；进程重启后继续处理，过期执行锁可重领。
3. AI 无风险的投稿进入待排期。AI 有风险或无法确认时，保留歌曲，通过主站 `service-tool` 通知告知用户「大概率不会被接受」，链接到「我的投稿」对应歌曲。
4. 用户阅读建议后选择「我已了解，仍要投稿」或「撤回投稿」。只有投稿人可确认，管理员不能代为确认。确认的是当前歌曲、当前规则和当前建议版本；变更后旧确认失效。
5. 通知成功送达后开始 24 小时计时。超过期限未确认的投稿，由后台任务自动撤回；确认过的投稿不因该建议过期而撤回。通知未成功送达不会启动倒计时。
6. 无论 AI 通过还是用户确认，进入待排期均不保证实际播出。技术故障不冒充内容风险，不触发确认期限；最多自动尝试三次，可在歌曲管理中重新发起 AI 检查。

用户歌曲卡片只显示“查看并处理”入口；建议在居中弹窗内完整展示，长内容独立滚动，确认/撤回按钮固定可见。管理员歌曲管理页面提供审核状态筛选、居中详情弹窗与来源、单曲/批量 AI 重审。排期候选仅列出可排期歌曲；直接排期、草稿、单独发布、批量发布和未播放排期恢复均执行服务端门禁。修改已排期歌曲的关键音源信息后，尚未播出的排期退回草稿。

## 证据与状态

- 复用主站 AI 调用、场景路由、回退及调用日志，不向浏览器提供 AI 密钥。
- 从固定音乐平台读取歌词/曲目信息，并使用主站已有联网搜索能力核实版本和公开来源。投稿人、联系方式等信息不发送给 AI。
- 标题、歌手、平台、音乐 ID、自定义播放地址和投稿人构成审核指纹。规则版本另行校验。
- 不信任模型自行编造的来源链接。仅对明确风险给出建议。资料缺失、音乐ID未核验、名称格式差异、未查到歌手舆情不作为风险；正常中文歌曲夹杂外语句子不误判。歌手项仅在有可信重大已证实事件时提示，不要求证明歌手没有争议，不虚构已听审音频。
- 有建议的投稿等待用户确认后停止自动重审，避免倒计时期间建议内容反复变化。管理员主动重审会产生新建议并重新通知。
- 通知采用稳定投递键去重；网络失败后重试不会重复创建同一建议通知。
- 用户确认、排期和撤回均锁住歌曲行。超时撤回时再次检查确认时间、歌曲指纹、规则版本及实际排期，已播放或正式排期的歌曲不会被误删。撤回事务同时清理关联记录并返还对应投稿时段名额。

## 部署和启用

需要同时更新主站服务、主站 Web 和 VoiceHub，并执行新增迁移 `20260927150000_add_song_reviews`。沿用 `VOICEHUB_INTEGRATION_SECRET` 与 `CPU_WEB_ORIGIN`，无需新密钥。

按仓库生产流程先验证提交对应 GitHub 构建产物，只有明确获得部署请求后才部署。启用开关后，存量未播放且未正式排期的歌曲也会进入检查。关闭开关暂停后台建议/过期处理，并恢复原排期行为。

测试使用模拟事务和本地 HTTP 服务，不访问生产数据库，不调用真实 AI、不发送真实通知。另以真实 Vue 组件和模拟响应验证审核详情及用户确认/撤回操作。

规则升级至v2后重新检查旧结论；旧规则的超时撤回不再执行。同一歌曲在相同管理员规则下已作出的用户确认，在此次放宽升级中保留。
